# Internationalization (en + pt-BR)

Source language is English; the second language is Brazilian Portuguese
(`pt-BR`). The engine is a small typed `t()` in `shared/src/i18n/`: no i18next,
no `Intl.PluralRules`, no ICU. This file is everything a conversion agent
needs: format, API, recipe, rules, checks, glossary.

## Mental model

- Every user-visible string lives in a **catalog**: three files in an `i18n/`
  directory next to the code that owns it (`en.ts`, `pt-BR.ts`, `index.ts`).
- Code calls `t('key', params)`. Keys, params and plural shapes are type-checked
  against the English catalog; a missing or extra pt-BR key is a `tsc` error.
- The active language is **one device-wide module singleton** (default `en`).
  Pure code (`domain/`, `*.logic.ts`, hooks) calls `t` directly: **no `t`
  parameter, no signature change, no test change.** Tests run in `en`.
- A language change **reloads the page on web** and **remounts the app tree on
  native** (`app/_layout.tsx`), so a component never shows stale text.
- Lint rule `budget-i18n/no-untranslated-string` finds strings you missed. It is
  switched on per file set by a manifest you add (see "Enforcement").

## Catalog format

```ts
// features/payees/i18n/en.ts: the source of truth
export default {
  'merge.title': 'MERGE PAYEE',
  'activity.count': { one: '{count} transaction', other: '{count} transactions' },
  'activity.lastUsed': '{count} · last used {date}',
} as const;

// features/payees/i18n/pt-BR.ts
import type { Translation } from '@shared/i18n';
import type en from './en';

const m: Translation<typeof en> = {
  'merge.title': 'MESCLAR FAVORECIDO',
  'activity.count': { one: '{count} transação', other: '{count} transações' },
  'activity.lastUsed': '{count} · último uso {date}',
};
export default m;

// features/payees/i18n/index.ts
import { defineMessages } from '@shared/i18n';
import en from './en';
import ptBR from './pt-BR';

export const t = defineMessages('payees', en, { 'pt-BR': ptBR });
```

- `en.ts` must end in `as const` (that is what gives `t` its literal types).
- Namespace name (first argument) is unique across the package; use the
  feature or area name. In `client/` the existing ones are `settings`,
  plus the shared `common` and `errors`; admin has `admin`.
- Where the directory goes: `client/src/features/<x>/i18n/`; one namespace per
  feature is the default, a second one in a sub-area (`features/banks/keys/i18n/`)
  is fine if the feature is large. Shared widgets in `ui/` use `ui/<area>/i18n/`.
  The catalog test finds every `**/i18n/index.ts` under `src/`.
- Import it as `import { t } from './i18n'` (same folder) or
  `import { t } from '../i18n'`. A feature's catalog is private to the feature:
  other features never import it (the eslint layering rule enforces barrels).
- Plain messages are strings with `{placeholders}`. Plurals are exactly
  `{ one, other }` (no `zero`, no ICU). A plural message always takes
  `count: number`. English plural: `count === 1` is `one`. pt-BR: `count` 0 and 1
  are `one` ("0 transação", "1 transação").
- Literal braces cannot be escaped; do not put `{` `}` in a message unless it is
  a placeholder.

### defineMessages options (4th argument, all optional)

```ts
defineMessages('x', en, { 'pt-BR': ptBR }, {
  sameAsEnglish: ['language.option.en'],   // pt-BR text intentionally identical (OK, brand words, language names)
  dynamicPrefixes: ['repeat.'],            // keys built as t(`repeat.${k}`): skip the "unused key" check for them
});
```

`sameAsEnglish` keys are checked against `en` (tsc error on a typo). A key
listed there whose pt-BR text actually differs fails the catalog test.

## The `t` API (`@shared/i18n`)

```ts
t('key')                                 // no placeholders
t('key', { name, count })                // params: string | number; names come from the English text
t('activity.count', { count: n })        // plural: count must be a number
t.for('pt-BR')('key', params)            // explicit locale, never pseudo-wrapped (API server only)
labels(t, { weekly: 'repeat.weekly' })   // table of labels with lazy getters (see recipe step 5)
parseRich(message)                       // pure tokenizer for <b>…</b>
```

Type behaviour (all compile errors): unknown key; missing param; param name not
in the English string; extra params on a message with no placeholders; plural
`count` that is not a number; `labels()` with a key that needs params.

Money and dates are **never formatted inside `t`**. Format with
`useMoneyFormat()` (components) or the `MoneyFormat` argument (pure code) and
pass the result as a string param: `t('x.total', { amount: money.formatMoney(c) })`.

Exported from `@shared/i18n`:

| export | meaning |
|---|---|
| `Locale` = `'en' \| 'pt-BR'`, `LOCALES`, `LOCALE_NAMES` | supported locales; names in their own language |
| `getLocale()`, `setLocale(l)`, `subscribe(fn)` | singleton; `subscribe` fires after a change |
| `resolveLocale(tags)` | device tags in preference order → `Locale` (first `pt*` → `pt-BR`, first `en*` → `en`, else `en`) |
| `defineMessages`, `labels`, `parseRich`, `registry()` | see above; `registry()` is for the catalog test |
| `setPseudoLocale(on)`, `isPseudoLocale()`, `getLocaleKey()` | dev pseudo-locale |
| types `Translation<E>`, `Translator<E>`, `ParamsOf<M>`, … | for `pt-BR.ts` and helpers |

Also: `tCommon` (`@shared/i18n/common`) and `tError` / `translateErrorCode`
(`@shared/i18n/errors`).

### Shared words: `tCommon` (frozen, never edit `shared/src/i18n/common/`)

`cancel save delete remove done close back edit add ok retry search loading`
(`Loading…`), `month.long.1-12`, `month.short.1-12`, `weekday.0-6` (Sunday = 0),
`weekday.min.0-6` (calendar headers), `date.long.dayFirst`, `date.long.monthFirst`.
Use `tCommon` only for these exact words (`tCommon('cancel')`). Anything else,
even "Save changes", belongs to your own namespace. For dates and months use
the helpers in `@/domain/format`, not `tCommon` directly:
`monthAbbr(m)`, `monthName(m)`, `weekdayAbbr(d)`, `weekdayMin(d)`, `formatMonth`,
`formatMonthLong`, `formatDateLongWith`. `MONTH_ABBR`, `MONTH_NAMES`,
`WEEKDAY_ABBR` still exist but are `@deprecated` and English-only; the lint rule
forbids importing them in enforced files (`MONTH_ABBR[i]` becomes `monthAbbr(i + 1)`).

### API errors: `tError` and `apiErrorMessage`

`shared/src/i18n/errors` has one message per API error code. A new code in
`shared/src/errors.ts` (`SPECIFIC_ERROR_CODES`) is a `tsc` error until both
`errors/en.ts` and `errors/pt-BR.ts` have it. In the client,
`apiErrorMessage(error, fallback?)` (`@/platform/api/baseQuery`) resolves:

1. a **specific** code with a message → that message (with the body's optional `params`);
2. the caller's `fallback` (translate it: `apiErrorMessage(err, t('rename.failed'))`);
3. the generic per-status message (`not_found`, `internal`, …);
4. the raw server text, only for a code this build does not know (or no code);
5. the generic `error` message.

So **pass a translated `fallback`** wherever there is a sentence naming the
action that failed ("Could not rename the payee"). With no fallback a
per-status error shows the generic message, not the server's English text.

## Key naming

Flat dotted keys, camelCase segments, **at most three**:
`<area>.<element>[.<variant>]`. Name the role, not the English text: `merge.title`,
`row.deleteButton`, `activity.lastUsed`, not `mergePayee` or `lastUsedDate`.
Keep casing as displayed: if the screen shows `MERGE PAYEE`, the English value is
`'MERGE PAYEE'` (and pt-BR is its own uppercase text). The catalog test rejects a
key that is not flat dotted camelCase (digits allowed in later segments).

## Recipe

1. Create or open your namespace; `import { t } from './i18n'`.
2. Replace each user-visible literal with `t('key', params)`; add the key to
   `en.ts` and `pt-BR.ts`.
3. **One sentence is one key.** Never concatenate translated fragments, never
   call `.toLowerCase()` / `.toUpperCase()` on a label to build a sentence. Word
   order differs between languages: put the whole sentence, with placeholders, in
   one message.
4. Replace hand-rolled plurals (`count === 1 ? '' : 's'`) with a `{ one, other }`
   message.
5. A module-level table of labels: wrap it with `labels(t, {…})` or turn the
   string field into a getter. **Never call `t()` at module scope**: it would
   freeze the language the app booted with (the lint rule reports it).
6. Do not change function signatures or test expectations. Tests run in `en`.
7. Use `tCommon` only for its seeded words; never edit `common/`.
8. Add your globs to `i18n-enforced/<id>.json`; run `bunx tsc --noEmit`,
   `bunx eslint .`, `bun test` (in `client/`).

Embedded elements (bold word, link inside a sentence): keep one key with tags and
render it with `rich` (`@/ui/i18n/rich`):

```tsx
// en: 'hint.save': 'Press <b>Save</b> to keep your changes'
<Text>{rich(t('hint.save'), { b: (children) => <Text style={styles.bold}>{children}</Text> })}</Text>
```

Tags nest; a tag without a renderer keeps its text. Params are interpolated
before parsing, so never pass user-typed text containing `<b>` as a param to a
message you render with `rich`.

Testing pt-BR (optional; the catalog test already checks keys and placeholders):

```ts
import { afterEach, test, expect } from 'bun:test';
import { setLocale } from '@shared/i18n';
afterEach(() => setLocale('en'));
test('pt-BR plural', () => { setLocale('pt-BR'); expect(activityLine(row)).toBe('0 transação · nunca usado'); });
```

// en.ts: two whole sentences, each plural (never "count" + "suffix")
'activity.lastUsed': { one: '{count} transaction · last used {date}', other: '{count} transactions · last used {date}' },

the two messages take different params and the type check needs them apart.

## Enforcement: the manifest

Each package you convert adds one file, `client/i18n-enforced/<package-id>.json`
(or `admin/i18n-enforced/…`):

```json
{
  "files": ["src/features/payees/**/*.{ts,tsx}"],
  "ignores": ["src/features/payees/legacy/**"]
}
```

`files` globs are relative to `client/` (or `admin/`); `ignores` is optional and
applies to that manifest only. `eslint.config.js` reads every JSON in the
directory from disk and applies the rule as `error` to the union: **nobody edits
`eslint.config.js`**, so parallel branches never conflict. List exactly the files
you converted, plus the "do not translate" files as `ignores` or with disable
comments. `i18n-enforced/README.md` repeats this.

### What the rule reports (`budget-i18n/no-untranslated-string`)

1. JSX text containing a letter.
2. A literal, template literal, or conditional/`??`/`||` of literals in a
   user-facing prop: `label title placeholder accessibilityLabel accessibilityHint
   aria-label sub desc description heading helper hint emptyText clearLabel confirm
   referenceLabel message text alt`.
3. An object property with one of those names holding a literal with a letter.
4. Any other literal or template that looks like prose: two words of two or more
   letters separated by a space, or a single capitalised word.
5. `t()` / `tCommon()` / `tError()` at module scope (outside any function or getter).
6. Imports of `MONTH_ABBR`, `MONTH_NAMES`, `WEEKDAY_ABBR` (enforced files).

Exempt automatically: arguments of `t`, `tCommon`, `tError`, `labels`, `console.*`,
`new Error` (and any `*Error`), `describe`/`test`/`it`, `require`; comparisons
(`===`, `!==`, `in`) and `case` labels; `.startsWith/.endsWith/.includes/.indexOf/.match`
and `RegExp` arguments; RTK Query tag lists (`tagTypes`, `providesTags`,
`invalidatesTags`, `invalidateTags(…)`); imports; type positions and enums;
`testID` and other non-text JSX props (`style`, `className`, `name`, `type`, …);
CSS-looking object keys (`fontFamily`, `border`, …) and `StyleSheet.create`;
colours, URLs, paths, numbers with units and markup strings; object keys; test
files, `__fixtures__/`, anything under an `i18n/` directory.

Known false-positive shapes (use the escape hatch, not a workaround): proper
nouns that are a single capitalised word (`'Itaú'`), currency or date-format
labels (`'R$'`, `'DD/MM/YYYY'`), key names shown as text (`'Esc'`), injected
JavaScript strings, TSV column headers.

### Escape hatch

```ts
// eslint-disable-next-line budget-i18n/no-untranslated-string -- brand name, not translated
const brand = 'Budget';
```

The reason after `--` is required in review. Use it for the "do not translate"
list below and for the false-positive shapes; never to skip real UI text.

## Do not translate

- `client/src/features/import/parsers/**` (bank file header matching).
- `features/backup/transfer/tsv.ts` and `payload.ts`, plus in `transfer.ts` the
  column headers, header checks, `'ready to assign'` / `'inflow'` matching and the
  zip file name. The **warnings and errors** `transfer.ts` shows to the person are
  user-visible and ARE translated.
- Stored system names used as identity: `'Reconciliation Adjustment'` compared in
  `domain/register.ts`, `TRANSFER_PAYEE_PREFIX` in `shared/src/domain/transfers.ts`.
  (The *display* of such a name is translated at the display site by mapping, not
  by changing the stored value.)
- Keyboard key names compared against events.
- Wire enum values; RTK tag and endpoint strings.
- `console.*`; developer `Error` text; tests and fixtures; zod `.describe()`;
  CLI and MCP text.
- The brand name "Budget".

## Pseudo-locale (find missed strings by eye)

Dev only. On web, open the app with `?lang=xa` (e.g. `http://localhost:8091/plan?lang=xa`):
every string that goes through `t`/`tCommon`/`tError` shows as `⟦text⟧`. Anything
without the brackets is still hard-coded. It is not a `Locale`, is not in
`LOCALES`, and is never offered in Settings. `t.for(locale)` is never wrapped.

## Language setting and boot (for reference; do not change)

- Preference `app.language` = `'system' | 'en' | 'pt-BR'` in the **device-level**
  KV store (not the per-budget settings blob: the landing and home pages render
  before a budget is active). Code: `client/src/platform/locale/`
  (`locale.ts`, `useLocale.ts`, `device.ts` / `device.native.ts`).
- `app/_layout.tsx`: `initDeviceLocale()` at module load (device language,
  synchronous), `initLocale(storage)` applies the stored override before children
  render, a `LocaleBoundary` keyed by `getLocaleKey()` remounts on change.
  **Why the remount**: the app uses the React Compiler, which may memoize `t()`
  results per component; without a remount a language switch could leave stale text.
- Web switches by **page reload** (`reloadApp()` in `device.ts`): remounting the
  tree resets expo-router to the home page (measured), a reload keeps the URL and
  the persisted active budget returns the person to the same screen. Native
  remounts.
- Hooks: `useLocale()`, `useLanguagePreference()` from `@/platform/locale/useLocale`.
  A component that needs to re-render on locale change without being under the
  boundary can use `useLocale()`; normal components do not need it.
- Admin: the locale follows the browser (`admin/src/main.tsx`), no setting.

## Checks

Run in the package you touched (install `shared/` first):

```
cd client && bunx tsc --noEmit && bunx eslint . && bun test
cd admin  && bunx tsc --noEmit && bunx eslint . && bun test
cd shared && bunx tsc --noEmit && bunx eslint . && bun test      # engine + the lint rule's own tests
```

`task typecheck`, `task lint`, `task test` run them all.

`client/src/i18n.test.ts` (same shape in `admin/src/i18n.test.ts` and
`shared/src/i18n/index.test.ts`) imports every `**/i18n/index.ts` and checks, per
namespace: same keys in en and pt-BR; same `{placeholder}` set per key; same plural
shape (`{ one, other }` only); no empty value; pt-BR identical to en only for keys
in `sameAsEnglish`; key names flat dotted camelCase; **no unused key** (every key
must appear as a string literal, `'key'`, in package source outside `i18n/` and
test files; keys built dynamically need `dynamicPrefixes`). `common` and `errors`
are exempt from the unused check. A failure message names the namespace and key.
